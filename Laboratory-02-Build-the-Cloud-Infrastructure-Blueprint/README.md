# Laboratory 02 - Build the Cloud Infrastructure Blueprint

## Mission Overview

This laboratory activity focused on exploring a Linux cloud environment and identifying the major resources that form cloud infrastructure. Through KillerCoda, I investigated system information such as the operating system, CPU, memory, storage, hostname, and IP address. The activity also included comparing major cloud providers and designing a simple cloud infrastructure diagram.

## Objectives

- Explore the system information available in a Linux cloud environment.
- Identify the major components of cloud infrastructure.
- Explain the role of compute, storage, networking, and operating system resources.
- Compare cloud services from AWS, Microsoft Azure, and Google Cloud Platform.
- Create a simple diagram representing cloud infrastructure.
- Organize and document the laboratory outputs using GitHub.

## Cloud Infrastructure Components

The cloud infrastructure components covered in this laboratory include:

- **Compute Resources** - Supply the processing power required to execute applications, commands, and workloads.
- **Storage Resources** - Provide space for storing files, programs, system data, and other information.
- **Networking Resources** - Allow users, servers, and other cloud resources to connect and communicate.
- **Operating System** - Manages the hardware and software resources and provides the environment needed to run applications.

## Tools Used

- **KillerCoda** - Provided the Linux environment used to investigate cloud infrastructure resources.
- **Linux Terminal** - Used to execute commands and examine server information.
- **GitHub** - Used to store and organize the documentation and screenshots for the laboratory activity.
- **Canva** - Used to create the cloud infrastructure diagram.

## Linux Commands Executed

- `cat /etc/os-release` - Used to identify the Linux operating system.
- `uname -r` - Used to check the Linux kernel version.
- `lscpu` - Used to examine the CPU model and CPU resources.
- `free -h` - Used to view the server's memory information.
- `df -h` - Used to check disk capacity and mounted file systems.
- `hostname` - Used to display the server hostname.
- `hostname -I` - Used to display the server's IP addresses.

## Skills Learned

This laboratory helped me become more familiar with basic Linux commands for examining the resources of a server. I learned how to identify compute, storage, networking, and operating system resources and understand their roles in a cloud environment.

I also developed a better understanding of the basic services provided by AWS, Microsoft Azure, and Google Cloud Platform. In addition, I practiced documenting technical information in GitHub and representing cloud resources through a simple architecture diagram.

## Challenges Encountered

One challenge during the activity was understanding the different information shown by Linux commands because some commands displayed many technical details. I needed to identify which parts of the output represented the CPU, memory, storage, and network information required by the activity.

Another challenge was connecting the Linux resources I observed to the concepts of cloud infrastructure. Reviewing each component and creating the architecture diagram made the relationship between these resources easier to understand.
