# Reflection — The Cloud Automation Engineer

Cloud automation is important when managing hundreds of cloud servers because it reduces repetitive manual work and helps tasks run consistently. Using scripts and scheduled jobs allows administrators to perform routine operations, such as backups, more efficiently. It also saves time and reduces the possibility of human error.

However, automation can be dangerous if it is not tested carefully. A destructive typo in a script scheduled to run on 1,000 servers could affect many systems before anyone notices. This is why scripts should be reviewed, tested in a safe environment, and monitored before being deployed widely. Backups and recovery plans are also important safeguards.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. Bash scripting involved writing commands, using variables, and controlling the order of operations to perform a task. Docker Compose YAML, on the other hand, described the configuration of services and how containers should run together. Both tools help automate cloud work, but they serve different purposes.

From Laboratory 1 to Laboratory 9, my understanding of cloud computing has developed from learning basic concepts to practicing infrastructure, deployment, operations, security, and automation. I learned that managing cloud systems involves more than making an application run. It also requires monitoring resources, protecting services, documenting configurations, and planning reliable operations.

The role I enjoyed most was the Cloud Security Engineer because securing systems and controlling network access showed me how important protection is in cloud environments. The security and automation missions also helped me understand that reliability depends on both proper configuration and consistent processes. Overall, these laboratory activities gave me practical experience and helped me appreciate the different responsibilities involved in cloud computing.
